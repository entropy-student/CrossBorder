# Sourcing Component Data Contract

Status: `v1.0.0` - sourcing-only contract. It is not the sellable Product
Master and has no direct Medusa import semantics.

## Boundary

The sellable contract in [`product/PRODUCT_DATA_CONTRACT.md`](../PRODUCT_DATA_CONTRACT.md) describes a
customer-facing Product Master. This contract describes a physical or
operational component that may later be used in a bundle BOM. A component can
be a real sourcing record without having a PDP handle, selling price, publish
status or Medusa product identity.

Supported component types:

- `CORE_COMPONENT`
- `ACCESSORY_COMPONENT`
- `PACKAGING_COMPONENT`

Supported lifecycle states include `CANDIDATE`, `SAMPLE_ORDERED`,
`SAMPLE_RECEIVED`, `SAMPLE_TESTING`, `SAMPLE_TESTING_PENDING`, `APPROVED` and
`REJECTED`. `SAMPLE_TESTING_PENDING` is retained as an explicit pending state
for the current COMP-001 intake.

The stable future bundle identifier for the current candidate is
`BUNDLE-PET-FUR-RESCUE-KIT`. This does not create a sellable bundle or a
Medusa product.

## Fact wrapper

Supplier-side values use an explicit fact wrapper where provenance matters:

```json
{
  "value": "AVAILABLE",
  "source": "SUPPLIER_CLAIM",
  "status": "NEEDS_VERIFICATION",
  "evidence": "supplier response / listing"
}
```

Allowed source labels are `SUPPLIER_CLAIM`, `IMAGE_EVIDENCE_ONLY`,
`SUPPLIED_FACT`, `PROJECT_DECISION` and `UNKNOWN_SOURCE`. `VERIFIED` is reserved
for independently verified facts; supplier statements in the current record
are not marked verified. An unknown fact uses `value: null` and
`status: UNKNOWN` or `NEEDS_VERIFICATION`.

## Required record sections

| Section | Required content |
|---|---|
| `identity` | Component ID, source product ID, supplier/source URL, platform and evidence |
| `role` | Component type, bundle candidate and candidate status |
| `cost` | Unit/batch/landed cost facts with currency and no inferred fees |
| `physical` | Product measurements/material and separate unit-package facts |
| `carton` | Carton quantities/measurements, never copied into unit package fields |
| `variants` | Image-only colorways unless supplier variant IDs are confirmed |
| `supplier_operations` | Stock, lead time, shipping, FBA/labeling and claim labels |
| `cross_border` | DDP terms/transit, supplier HS with verification status and origin |
| `risk` | FTO, patent, compliance and unresolved risks without legal conclusions |
| `sample` | Sample quantity/cost/shipping/test and refund conditions |
| `procurement` | Candidate status, bulk-order gate and approval/rejection reason |

`supplier_operations.bulk_shipping_quote` is the required structured quote
for a bulk shipment. It contains `destination`, `quantity`, `mode`,
`quoted_cost`, `currency`, `terms`, `transit_time`, `source`, `status` and
`evidence`. It replaces the ambiguous `domestic_shipping` field; this quote
is not domestic shipping and is not automatically verified.

## Gate meanings

The component validator reports independent gates:

- `SOURCE_GATE`: traceable source identity and supplied evidence.
- `SAMPLE_GATE`: sample order/receipt/testing readiness.
- `PROCUREMENT_GATE`: whether bulk ordering is allowed; `HOLD` is not approval.
- `LOGISTICS_GATE`: package/origin/HS/shipping facts are sufficiently verified.
- `RISK_GATE`: FTO/compliance/material and unresolved-risk review.

`COMPONENT_RECORD=NEEDS_VERIFICATION` is expected for COMP-001. It does not
authorize purchase, consumer sale, Medusa import or a formal bundle launch.

## Relationship to BOM

A BOM references the stable `bundle_id`, then `component_id` and quantity. Component cost and landed
component cost can be calculated when the relevant facts are known. Packaging
cost and final bundle COGS remain unknown until packaging and every bundle
component are supplied. The current draft BOM contains only `COMP-001 x 1`
and is not a final Kit BOM. A bulk quote must be reconfirmed before any bulk
order decision.
